```python
import mysql.connector
from mysql.connector import Error

def connect_and_test_database():
    try:
        # Kết nối đến MariaDB
        connection = mysql.connector.connect(
            host='localhost',        # hoặc 127.0.0.1
            port=3306,               # port được expose từ container
            database='studentdb',    # tên database
            user='root',            # username
            password='root'         # password
        )

        if connection.is_connected():
            print("✅ Kết nối thành công đến MariaDB!")
            print(f"📊 Server version: {connection.get_server_info()}")

            # Tạo cursor để thực hiện queries
            cursor = connection.cursor()

            # Hiển thị thông tin database hiện tại
            cursor.execute("SELECT DATABASE();")
            db_name = cursor.fetchone()
            print(f"📋 Database hiện tại: {db_name[0]}")

            # Hiển thị danh sách tables
            cursor.execute("SHOW TABLES;")
            tables = cursor.fetchall()
            print("📋 Danh sách tables:")
            for table in tables:
                print(f"  - {table[0]}")

            # Hiển thị dữ liệu trong bảng students
            cursor.execute("SELECT * FROM students;")
            students = cursor.fetchall()
            print("\n👥 Danh sách sinh viên trong studentdb:")
            print("ID | Student ID | Full Name | DOB | Major")
            print("-" * 60)
            for student in students:
                print(f"{student[0]} | {student[1]} | {student[2]} | {student[3]} | {student[4]}")

            # Thực hiện một số CRUD operations mẫu
            print("\n🔄 THỰC HIỆN CRUD OPERATIONS:")

            # CREATE - Thêm sinh viên mới
            print("\n➕ CREATE: Thêm sinh viên mới")
            cursor.execute("""
                INSERT INTO students (student_id, fullname, dob, major)
                VALUES (%s, %s, %s, %s)
            """, ('SV004', 'Nguyen Van D', '2003-06-15', 'Data Science'))
            connection.commit()
            print("✅ Đã thêm sinh viên SV004")

            # READ - Đọc dữ liệu
            print("\n📖 READ: Hiển thị sinh viên ngành Computer Science")
            cursor.execute("SELECT * FROM students WHERE major = 'Computer Science';")
            cs_students = cursor.fetchall()
            for student in cs_students:
                print(f"  - {student[1]}: {student[2]}")

            # UPDATE - Cập nhật thông tin
            print("\n✏️ UPDATE: Cập nhật ngành học của SV004")
            cursor.execute("""
                UPDATE students SET major = 'AI & Data Science'
                WHERE student_id = 'SV004'
            """)
            connection.commit()
            print("✅ Đã cập nhật ngành của SV004")

            # DELETE - Xóa sinh viên
            print("\n🗑️ DELETE: Xóa sinh viên SV004")
            cursor.execute("DELETE FROM students WHERE student_id = 'SV004';")
            connection.commit()
            print("✅ Đã xóa sinh viên SV004")

            print("\n🎉 Đã hoàn thành tất cả CRUD operations!")

    except Error as e:
        print(f"❌ Lỗi kết nối database: {e}")
        print("💡 Kiểm tra:")
        print("  - Container MariaDB đã chạy: docker compose ps")
        print("  - Port 3306 không bị block")
        print("  - Firewall cho phép kết nối đến localhost:3306")

    finally:
        if 'connection' in locals() and connection.is_connected():
            cursor.close()
            connection.close()
            print("🔌 Đã đóng kết nối database.")

if __name__ == "__main__":
    connect_and_test_database()
```

   **CÁCH 1: Sử dụng PowerShell (Windows) - KHUYẾN NGHỊ**

   a) Lệnh cơ bản để lấy token:
   ```powershell
   $response = Invoke-WebRequest -Uri "http://localhost:8081/realms/realm_sv189/protocol/openid-connect/token" `
     -Method POST `
     -Headers @{"Content-Type"="application/x-www-form-urlencoded"} `
     -Body "grant_type=password&client_id=flask-app&client_secret=abc123def456&username=sv01&password=password123"

   $token = ($response.Content | ConvertFrom-Json).access_token
   Write-Host "Access Token: $token"
   ```

   b) Tạo file PowerShell script để tái sử dụng:
   ```powershell
   # Tạo file get_keycloak_token.ps1 với nội dung:
   function Get-KeycloakToken {
       param(
           [string]$RealmId = "realm_sv189",
           [string]$ClientId = "flask-app",
           [string]$ClientSecret = "abc123def456",
           [string]$Username = "sv01",
           [string]$Password = "password123"
       )

       $uri = "http://localhost:8081/realms/$RealmId/protocol/openid-connect/token"
       $body = "grant_type=password&client_id=$ClientId&client_secret=$ClientSecret&username=$Username&password=$Password"

       try {
           $response = Invoke-WebRequest -Uri $uri -Method POST -Headers @{"Content-Type"="application/x-www-form-urlencoded"} -Body $body
           $tokenData = $response.Content | ConvertFrom-Json
           return $tokenData.access_token
       }
       catch {
           Write-Error "Failed to get token: $($_.Exception.Message)"
           return $null
       }
   }

   # Cách sử dụng:
   $token = Get-KeycloakToken
   Write-Host "Token: $token"
   ```

   c) Chạy script:
   ```powershell
   # Load script
   . .\get_keycloak_token.ps1

   # Lấy token
   $token = Get-KeycloakToken
   Write-Host "Access Token: $token"
   ```

**CẤU HÌNH BUCKET PERMISSIONS (Quan trọng!):**

Sau khi tạo bucket, cần cấu hình permissions để cho phép public access:

1. **Trong MinIO Console:**
   - Click vào bucket **"profile-pics"**
   - Trong Object Browser, tìm nút **"Access"** hoặc **"Policy"** (thường ở góc phải)
   - Click vào **"Access: PRIVATE"** để thay đổi
   - Chọn **"Public"** hoặc **"Read Only"**
   - Hoặc tìm **"Bucket Policy"** trong menu settings

   **Nếu không thấy tùy chọn trong UI:**
   - Sử dụng **Manage** button (biểu tượng bánh răng)
   - Chọn **"Access Policy"** từ dropdown menu

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {"AWS": "*"},
      "Action": ["s3:GetObject"],
      "Resource": ["arn:aws:s3:::profile-pics/*"]
    }
  ]
}
```

2. **Via MinIO Client:**
```bash
# Set bucket policy cho public read
mc policy set download local/profile-pics

# Hoặc set policy JSON
mc policy set-json local/profile-pics policy.json
```

3. **Via API:**
```bash
# Set bucket policy
curl -X PUT "http://localhost:9000/profile-pics?policy" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "Version": "2012-10-17",
    "Statement": [
      {
        "Effect": "Allow",
        "Principal": {"AWS": "*"},
        "Action": ["s3:GetObject"],
        "Resource": ["arn:aws:s3:::profile-pics/*"]
      }
    ]
  }'
```

**Lưu ý về Share Links:**
- Share links của MinIO thường có format dài và phức tạp
- Có thể bị cắt trong một số giao diện
- Thường có thời hạn expire
- **Khuyên dùng Direct URL cho production**

**Lưu ý quan trọng:**
- **File permissions:** Để URL public hoạt động, bucket cần được cấu hình public access
- **File size:** MinIO hỗ trợ upload file lớn, nhưng có giới hạn network
- **File types:** Hỗ trợ tất cả loại file, nhưng cho avatar nên dùng JPG/PNG
- **Naming:** Sử dụng tên file có nghĩa để dễ quản lý

**Troubleshooting:**
- **Access Denied:** Cấu hình bucket permissions (xem hướng dẫn trên)
- Upload thất bại: Kiểm tra network connection và credentials
- URL không truy cập được: Kiểm tra bucket permissions
- Ảnh không hiển thị: Kiểm tra file format và browser cache
- Share link bị cắt: Dùng direct URL `http://localhost:9000/{bucket-name}/{file-name}`

**Mục tiêu:** Hiểu về DNS (Domain Name System) và cấu hình internal DNS server
**Lợi ích:** Cho phép các container giao tiếp với nhau qua domain names thay vì IP addresses
**Công nghệ:** BIND9 DNS server chạy trong Docker container

BUOC 6.1: KHOI DONG DNS CONTAINER
--------------------------------
**DNS là gì?**
DNS (Domain Name System) là hệ thống phân giải tên miền thành địa chỉ IP.
Trong microservices architecture, DNS giúp các service tìm và giao tiếp với nhau.

**Khởi động DNS server:**
```bash
# Khởi động container DNS
docker compose up -d internal-dns-server

# Kiểm tra trạng thái container
docker compose ps

# Xem logs để đảm bảo DNS server khởi động thành công
docker compose logs internal-dns-server
```

**Expected output:**
```
NAME                    IMAGE                                  STATUS
internal-dns-server     internetsystemsconsortium/bind9:9.18   Up
```

**DNS Server specs:**
- **Port:** 1053/UDP (không phải port 53 standard để tránh conflict với host DNS)
- **Domain:** cloud.local
- **Type:** Authoritative DNS server cho internal network

BUOC 6.2: HIỂU VỀ DNS RECORDS & ZONE FILES
------------------------------------------
**DNS Records là gì?**
- **A Record:** Map domain name → IPv4 address
- **NS Record:** Name Server record
- **SOA Record:** Start of Authority (thông tin zone)

**Zone File structure:**
```
$TTL 1H          ; Time To Live (1 hour)
@ IN SOA ns.cloud.local. admin.cloud.local. (
    1           ; Serial number
    1H          ; Refresh (1 hour)
    15M         ; Retry (15 minutes)
    1W          ; Expire (1 week)
    1H          ; Negative TTL (1 hour)
)
    IN NS ns.cloud.local.    ; Name Server
ns  IN A  127.0.0.1          ; NS points to localhost
```

**Các DNS records trong hệ thống:**
- **web-frontend-server:** Frontend web app (Nginx)
- **app-backend.cloud.local:** Flask backend API
- **minio.cloud.local:** MinIO object storage
- **keycloak.cloud.local:** Keycloak authentication

BUOC 6.3: XEM & HIỂU ZONE FILE HIỆN TẠI
-------------------------------------
```bash
# Xem nội dung zone file
cat internal-dns-server/db.cloud.local
```

**Nội dung chi tiết của file db.cloud.local:**
```
$TTL 1H
@   IN  SOA ns.cloud.local. admin.cloud.local. (1 1H 15M 1W 1H)
    IN  NS  ns.cloud.local.
ns  IN  A   127.0.0.1

; Service records
web-frontend-server     IN A 10.10.10.10
app-backend.cloud.local IN A 10.10.10.20
minio.cloud.local       IN A 10.10.10.30
keycloak.cloud.local    IN A 10.10.10.40
```

**Giải thích từng record:**
- `web-frontend-server IN A 10.10.10.10` → Frontend service
- `app-backend.cloud.local IN A 10.10.10.20` → Backend API
- `minio.cloud.local IN A 10.10.10.30` → Object storage
- `keycloak.cloud.local IN A 10.10.10.40` → Authentication service

Khi thay đổi zone file, DNS server cần được restart để load cấu hình mới.


BUOC 6.5: TEST DNS RESOLUTION CHI TIẾT
-----------------------------------
**Quan trọng về Docker DNS:**
- Docker containers mặc định sử dụng internal DNS resolver (127.0.0.11)
- DNS server của chúng ta chạy trên port 1053 (external access)
- Trong Docker network, containers có thể truy cập nhau bằng service names
- DNS server này chủ yếu để demo và hiểu khái niệm DNS resolution

**1. Test từ container khác (recommended):**
```bash
# Test từ backend container (nó sẽ dùng DNS server internal)

# Test từng service

    docker exec application-backend-server nslookup keycloak.cloud.local internal-dns-server
```

**Expected output:**
```
Server: internal-dns-server
Address: 172.18.0.XX#53

Name: app-backend.cloud.local
Address: 10.10.10.20
```

**2. Test từ host với dig (Linux/Mac):**
```bash
# Chỉ định port 1053

# Hoặc dùng drill (alternative to dig)
drill @127.0.0.1 -p 1053 app-backend.cloud.local
```

**3. Test từ Windows PowerShell:**
```powershell

```

**4. Test thực tế - từ application container:**
```bash

```

BUOC 6.6: TROUBLESHOOTING DNS ISSUES
----------------------------------
**Nếu DNS không hoạt động:**

**1. Kiểm tra container status:**
```bash
docker compose ps
# DNS container phải ở trạng thái "Up"
```

**2. Kiểm tra logs:**
```bash
docker compose logs internal-dns-server
# Tìm lỗi syntax trong zone file
```

**3. Validate zone file:**
```bash
# Kiểm tra syntax zone file
docker exec internal-dns-server named-checkzone cloud.local /etc/bind/db.cloud.local
```

**4. Test port connectivity:**
```bash
# Kiểm tra port 1053 có mở không
netstat -an | findstr 1053
# hoặc
telnet 127.0.0.1 1053
```

**5. Common issues:**
- **Zone file syntax error:** Kiểm tra định dạng SOA record
- **Port conflict:** DNS server khác đang dùng port 53
- **Firewall blocking:** Windows Firewall block UDP port 1053
- **Container networking:** DNS container không thể bind port

**6. Fix common problems:**
```bash
# Restart với clean state
docker compose down
docker compose up -d internal-dns-server

# Force reload zone
docker exec internal-dns-server rndc reload

# Windows alternative (nếu rndc không hoạt động)
docker compose restart internal-dns-server
```

- **Reliability:** DNS là single point of failure → cần monitoring
